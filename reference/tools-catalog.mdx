## Overview

SAGO provides **73 auto-discovered tools** organized into modular categories. All tools are executed within an OpenAI-compatible function-calling loop with risk-based permission gating and automatic error recovery.

---

## Risk-Based Permission System

Tools are assigned a risk level to prevent accidental modifications or destructive operations:

| Risk Level | Representative Tools | Default Behavior |
|---|---|---|
| **Safe** | `read_file`, `glob_files`, `grep_content`, `env_info`, `os_detector`, `web_search`, `web_fetch` | **Auto-approved** |
| **Low** | `write_file`, `edit_file`, `file_operations`, `archive`, `code_sandbox` | **Auto-approved** |
| **Medium** | `execute_shell`, `background_process`, `docker_ops`, `k8s_ops`, `browser` | **Requires user approval** |
| **High** | `ssh_connect`, `ssh_command`, `sudo_executor` | **Requires user approval** |
| **Critical** | `spawn_agent` | **Requires user approval** |

<Note>
In TUI or headless mode, you can bypass permission confirmations by toggling YOLO mode with `/yolo on` or passing the `--yolo` CLI flag.
</Note>

## Error Handling & Recovery

Every tool invocation is protected by the `sago/errors/handler.py` recovery engine:
1. **Self-Correction:** If a tool call fails (e.g. `read_file` on a directory), the engine consults `LearningStore` for known fixes.
2. **Crash Prevention:** A failing tool returns a clean diagnostic error message back to the LLM turn loop rather than terminating the agent process.
3. **Audit Tracing:** Microsecond tool latencies, parameters, and outputs are logged to the Developer Inspector (<kbd>F2</kbd>).
